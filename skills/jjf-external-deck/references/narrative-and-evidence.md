# 叙事与证据

## JJF 品牌关系

主品牌为 JJF AI Craft Labs / JJF AI造物实验室。OPC 是本次政府/园区合作的业务叙事，不应永久取代主品牌。可将社区、能力加速、FDE交付、原型实验室、全球开发者网络作为能力模块，但本会话中提出的 Builder Network / OPC Academy / FDE Studio / Global Hacker House 是命名建议，不等于已注册产品或已建成机构。

## 先选择受众

政府/园区版：人才、招商、产业转化、可考核运营。集团/企业版：业务问题、场景、MVP验证、质量、验收、业务协同。开发者/社区版：能力、伙伴、作品、机会与归属。培训版：适合人群、项目成果、学习路径、真实课程案例。海外活动版：主题、招募、驻留共创、合作方与赞助交付。不要把亲子课和政府产业方案用一套服务清单机械拼接。

一般顺序：对方问题→JJF的角色→具体方法→可信证据→如何启动→合作行动。先讲价值再讲能力，不以长篇政策开头。避免“全链路、全生态、一站式”反复替代具体动作。

## 本次 OPC 表达

封面工作稿主张：从一人创新，到一城产业。
方案名：JJF OPC 生态运营与联合交付方案。
具体价值：让 OPC 不只入驻，更能接单、交付、增长。
核心组织：社区增长引擎×联合交付引擎。
成长路径：招募、评估、培育、共创、对接、增长。
资本与海外网络：合作机会与放大机制，不是保证融资和保证出海。

“一城产业”是愿景，不是已实现业绩。OPC在本方案中是AI增强的一人/极小团队经营单元，不强作工商法律定义。需要讨论法律认定时另查官方依据。

## 证据分级

`verified`（有可追溯可靠来源）、`user_supplied`（用户自述/内部文件）、`planned`（计划与投标承诺）、`illustrative`（示例）、`needs_confirmation`、`conflicted`、`expired` 分别记录。只有允许公开、状态与措辞匹配、无冲突的条目能发布。用户自述可用克制的自述措辞，但不得标成独立第三方核实。

案例必须有：项目名称、时间地点、JJF真实角色、问题、动作、产物、证据文件、允许公开范围。主办≠协办≠受邀讲者≠参赛≠参会；个人履历≠JJF公司业绩。未提供真实照片时案例布局标“资料待补”，或用明确的概念示意；不能自造“现场”。

团队数字：旧官方介绍社区200+，投标材料写2000+；二者可能是不同群体，也可能冲突，不能替用户推断“200活跃/2000触达”就是事实。需要定义统计口径、时间、去重方式和主体后才能采用。奖项20+/5+/30+同理，不能简单相加。

投标材料：活动数、导师次数、投资对接次数在不同章节不一致，先进入冲突台账；年度目标不是历史完成。1+2+N是该项目组织承诺，不自动作为所有客户的标准价格/人员配置。120万元报价及付款条款为内部商务材料，不带进通用宣传默认包。

政策：本会话粘贴的“待出台”OPC措施、实施细则送审稿、翔安建议条款均不能写成生效权益；思明政策不能不加地域条件套到翔安。即使源表标了官方链接，复用时也要重新核发布日期、有效期、申报主体、费用口径与叠加规则。Skill不固化当前补贴金额，不承诺可兑现。

空间：概念建议、规划席位、消防复核条件不可改写成已建成可用能力。需要引述容量或面积时保留“规划/建议/需复核”等来源状态。
